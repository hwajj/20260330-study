# study-session-start

SSOT: `STUDY-PLAN-8W.md`. **쓰기:** `log/_common/sessions/active.md` (다른 PC는 git pull 후 이 파일 이어서).

**원칙:** `active.md`만 열어도 **무엇을·어디서·몇 분·무엇을 남기는지** 알 수 있어야 한다.  
한 줄 요약(「노트 3줄」「종이만」)만 쓰지 말고, 아래 **실행 체크리스트**를 채운다.

## 1. 읽기 (최소)

**한 번에 병렬로:**

| 대상 | 방법 |
|------|------|
| `CURRENT_WEEK`, `CURRENT_DAY`, `CURRENT_CURR_DAY` | `STUDY-PLAN-8W.md` 상단 ~20줄만 |
| §4-B 해당 주 행 1줄 | grep `\| \*\*{week}\*\* \|` |
| §4-A `### Week {week}` | grep 후 **그 블록만** Read (다른 Week 금지) |
| §10 `막힌 질문` 1줄 | grep |
| 이론 **파일 경로** | `CURRICULUM-FULL-TRACK.md`에서 `CURRENT_CURR_DAY` slug **한 줄** (md 상대 경로 전체) |
| 사고력 **오늘 슬롯** | `PS-TRACK-8W.md` — `## 5. Week {week}` 블록 있으면 Read; 없으면 **§2 요일 표** + §4 Study W{week} 행만 grep |

**읽지 않기:** `CURRICULUM-BRIDGE-8W.md` 전체, §3·§2 전문 전체.

## 2. 요일 `day`

1. 사용자가 Week/요일 지정 → 그대로 (Week 없으면 `CURRENT_WEEK`).
2. 아니면 `week=CURRENT_WEEK`, `day=CURRENT_DAY`.
3. §4-B에서 `day`가 ☑ → 월→일 **첫 ☐**.
4. 주 7칸 전부 ☑ → 채팅·파일에 «주 완료»만, §4-A 과제 출력 생략, wrap·W+1 제안.

## 3. `active.md` (필수, start마다)

경로: `log/_common/sessions/active.md` (없으면 `log/_common/sessions/` 생성).

**같은 `W{week}-{day}`로 재시작:** 기존 `## 진행` / `## 메모` / `## 막힌 질문` **유지**, `## 실행 체크리스트`만 갱신.

**다른 주·요일:** 기존 `active.md` 내용은 `log/_common/sessions/archive/{YYYY-MM-DD}-W{w}-{day}.md`로 옮긴 뒤 새 `active.md`.

### 3-A. 섹션 구성 (고정 순서)

1. `#` 헤더 + pull 안내 (기존과 동일)
2. **`## 실행 체크리스트`** — 아래 3-B~3-E **전부** nested `- [ ]` (4~15개 항목 OK)
3. **`## 이번 주 한 줄`** — §4-A 주 목표 또는 금요 통과 1줄
4. **`## 참고`** — 막힌 질문, 플랜 커서 한 줄
5. **`## 진행` / `## 메모` / `## 막힌 질문`** — 사용자 영역 (빈 템플릿)

**삭제·축약 금지:** `## 오늘 할 일` 4줄 요약만 두고 끝내지 않는다. 요약이 필요하면 체크리스트 **맨 위**에 «오늘 4블록: 이론·회사·사고력·저녁» 한 줄만.

### 3-B. 이론 — 항상 이 4칸 (§3 STUDY-PLAN)

`{theory_path}` = FULL-TRACK grep의 md 경로. `{slug}` = `CURRENT_CURR_DAY`. `{title}` = 표 제목.

```markdown
### 이론 — {title} (회사 60~90m)
- [ ] **열기:** `{theory_path}` (워크스페이스에 없으면 링크 따라 `frontend-dev-notes` 위치 확인)
- [ ] **읽기:** 문서 **전체 1회** (표·코드 블록 포함). 모르는 용어는 옆에 ? 표시만
- [ ] **남기기:** `log/_common/curriculum-notes/{slug}.md` 생성·추가 — **나만의 말로 정확히 3줄** (①정의 ②다른 개념과 차이 ③FE/회사와 연결)
- [ ] **면접:** `frontend-dev-notes/docs/interview/index.md`에서 **오늘 주제** 질문 1개 골라 **소리 내서 30초+** 답 → 같은 노트 파일 맨 아래 `면접 Q:` / `내 답 요지:` 각 1줄
```

### 3-C. 회사 — §4-A 해당 요일 행 → 실행화

§4-A **회사 (추가)** + **열 파일**을 아래처럼 쪼갠다.

```markdown
### 회사 — 코드 리딩 (20~40m, 손코딩·수정 X)
- [ ] **열기:** `{열 파일 전체 repo 상대 경로}`
- [ ] **범위:** §4-A «회사» 문장에 맞는 심볼·구간만 (**50~80줄** 또는 해당 함수 전체)
- [ ] **할 일:** {§4-A 회사 한 줄을 동사로 — 예: «AsyncQueue 클래스 **주석** 읽고 enqueue/dequeue 순서 메모»}
- [ ] **남기기:** `## 메모`에 **2문장** — (1) 이 코드가 막는 문제 (2) 내가 헷갈리는 점 1개
```

이론이 길어 회사를 미룬 날은 체크리스트에 «오늘 회사 스킵 — 내일 `{path}`» 한 줄 명시.

### 3-D. 사고력 (§4-C) — 요일별 **복사 템플릿**

`PS-TRACK` `Week {week}`에 **메인 문제명·링크·예시 입력**이 있으면 그걸 넣는다. 없으면 §4-C 주차 표 유형 + §2 해당 요일 행만으로 채운다.

**월**

```markdown
### 사고력 — 문제 선정 (회사 10m)
- [ ] `PS-TRACK-8W.md` Week {week} **메인 1개** 링크 확정 (없으면 프로그래머스에서 §4-C 주제 유형으로 1개)
- [ ] `log/_common/sessions/active.md` → `## 메모`에 `PS 메인: {제목} {URL}`
- [ ] 난이도·유형 한 줄 (예: Lv.2 큐 시뮬레이션)
```

**수** (회사 **20~30m**, IDE·코드 **금지**)

```markdown
### 사고력 — 종이 trace (회사 20~30m, 코드 X)
- [ ] **문제:** {메인 제목} — 링크: {URL} (월에 안 골랐으면 Week {week} 고정안 메인 사용)
- [ ] **3m** 지문 → 종이 상단에 입·출·제약 **한 문장**
- [ ] **10m** 예시 입력 `{구체 예}` 로 표 trace (`step | 상태 | 출력` 열은 PS-TRACK §3 따름)
- [ ] **10m** invariant **한 줄** (본인 문장; PS 힌트 문장 베끼기 X)
- [ ] **5m** 엣지 3개 **말로만** (빈 입력·길이 1·최악)
- [ ] **남기기:** `docs/notes/{YYYY-MM-DD}_ps-{slug}.md` 초안 5줄 (PS-TRACK §1 템플릿)
```

**금**

```markdown
### 사고력 — 구현 (30~40m, AI OFF)
- [ ] **파일:** `src/labs/ps/week{week}-{slug}.ts` 에 이번 주 **메인** 구현
- [ ] 로컬에서 통과 확인 후 복기 카드 `docs/notes/...` **FE 연결** 줄 완성
```

**화·목**

```markdown
### 사고력 — 복기 (저녁 15m, 코드 X)
- [ ] **열기:** 이번 주 메인 문제 복기 카드 (`docs/notes/..._ps-*.md`)
- [ ] invariant **소리 내서 1번**; 막힌 단계 있으면 카드 **1줄 수정**
```

**토**

```markdown
### 사고력 — 가볍게 (선택 10m)
- [ ] Week {week} **서브** 문제 trace **또는** 메인을 예시 입력 하나 **말로 5분**
```

**일**

```markdown
### 사고력 — 휴식 (선택 5m)
- [ ] 복기 카드 **읽기만** (체크 안 해도 됨)
```

**공통:** 저녁 90m FE와 **같은 시간대에 구현하지 않음** (금·주말 분리).

### 3-E. 저녁 90m — §4-A «저녁» → 단계

```markdown
### 저녁 90m — FE 손과제 (AI OFF)
- [ ] **준비:** 타이머 90m, AI·챗 끄기
- [ ] **할 일:** {§4-A 저녁 열 — 동사·산출물 명시}
- [ ] **산출물:** {종이 1장 / 콘솔 로그 캡처 / 파일 경로} — 완료 기준 1줄
- [ ] **끝:** `## 진행`에 완료 시각·통과/미통과 한 줄
```

예 (W1 수): 401 시나리오 A,B,C + reissue 1회 → 종이 열 `t | 요청 | 큐 | reissue? | 결과` + **2분 말로 설명**.

### 3-F. 주말 (토·일)

`## 실행 체크리스트`에 §4-A **`주말:`** 문장을 3~5개 `- [ ]`로 쪼갠다 + 위 **토/일 사고력** 템플릿.

### 3-G. 완성 예 (구조만 참고)

W1 수요일이면 이론 4 + 회사 4 + 수 사고력 6 + 저녁 4 ≈ 18칸. **모든 칸에 경로·시간·남길 파일**이 있어야 한다.

## 4. 채팅 출력 (짧게)

- «**W{n} {day}** — `active.md`에 실행 체크 {N}개 적어 뒀어요» + **4블록 제목만** (이론/회사/사고력/저녁) 각 1줄
- «자세한 건 `log/_common/sessions/active.md`의 `## 실행 체크리스트`»
- 표·§ 원문·긴 맥락 **금지**

## 5. 하지 않기

- `STUDY-PLAN-8W.md` 커서/§4-B **수정** (wrap만)
- 손코딩 **전체 정답 코드**
- 파일 저장 없이 start만 끝내기
- «노트 3줄」「종이만」같은 **비실행** 한 줄 체크만 남기기
