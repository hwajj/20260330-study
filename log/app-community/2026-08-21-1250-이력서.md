# app-community (커뮤니티 · 대화방)

## 한 줄 요약
커뮤니티 앱에서 결제·수락 상태와 연동된 1:1 대화방을, HTTP 히스토리와 Socket.IO 실시간 갱신을 분리해 구현한 프론트엔드 기능.

## 기술 스택 / 역할 키워드
- Vite, React 18, TypeScript
- Socket.IO Client, Axios
- Redux Toolkit (미읽음 총합), TanStack Query (프로필·결제 연계)
- React Router (목록 / 방 / 전체보기 lazy 라우트)

## 이력서 불릿
- 대화방 메시지 히스토리는 HTTP 페이지네이션으로 두고, 실시간 수신·전송은 Socket.IO로 분리해 방 진입·퇴장 시 읽음 처리와 구독 해제를 훅에서 관리함
- 목록은 소켓으로 초기 로드한 뒤 방별 `chat:list:update:{roomId}`로 lastMessage·unread만 갱신하고, 총 미읽음은 Redux로 Navbar 배지에 반영함
- 방 상태(`R` 수락대기 / `Y` 대화중 / `N`·`C` 종료)에 따라 입력 비활성·플레이스홀더·나가기 모달 문구를 분기해 결제·재연결 정책을 UI에 맞춤
- 위로 스크롤 시 이전 메시지 더보기와 스크롤 높이 보정으로, 히스토리 prepend 후에도 읽던 위치를 유지함
- 시스템 메시지의 `sys_btn_type` 비트 플래그로 프로필·수락·바로대화 CTA를 렌더하고, 수락/요청은 결제 화면으로 연결함
- 프로필·피드의 대화하기는 결제 정보 조회 후 기존 `chat_id`면 방으로, 없으면 결제 요청으로 라우팅해 진입 경로를 통일함
- 긴 텍스트는 줄 수 측정 후 전체보기 페이지로 넘기고, 시스템 HTML은 DOMPurify로 허용 태그만 sanitize함

## STAR
### 1. 실시간 목록·미읽음과 방 메시지 채널 분리
- S: 목록 화면과 방 안에서 각각 다른 갱신 단위(행 미리보기 vs 메시지 스트림)가 필요함
- T: 폴링 없이 목록·배지·방 메시지를 일관되게 갱신하는 클라이언트 구조를 잡음
- A: `createChatSocket`으로 emit/on을 도메인 API로 감싸고, `useChatList`는 방별 업데이트·총 unread, `useChatRoom`은 join/leave·HTTP 히스토리·`result:chat:message`를 담당함
- R: (사용자 제공 수치 없음)

### 2. 대화 상태·결제와 맞춘 전송/나가기 UX
- S: 유료 1:1 대화라 수락 전·대화중·종료 후 행동이 다름
- T: 잘못된 전송·모호한 종료 확인을 막고 결제 플로우로 이어지게 함
- A: `room_chat_status`·`role_type`으로 입력 제어, 목록 나가기는 상태별 모달 후 DELETE, CTA는 payment query로 연결함
- R: (사용자 제공 수치 없음)
