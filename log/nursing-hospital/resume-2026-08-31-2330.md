# nursing-hospital (요양원-물류센터 물류 관리 콘솔)

## 한 줄 요약

기획·디자인·프론트·MVP 백엔드를 AI 에이전트 워크플로로 일관 구축한 요양원-물류 데스크톱 어드민 — Cursor Rules/Skills·기획 SSOT·TDD 루프로 AI 출력을 검증·제약하고, 주문 관리 도메인을 end-to-end로 구현.

## 기술 스택 / 역할 키워드

- React 19, TypeScript, Vite 8, Tailwind CSS 4
- React Router 6, TanStack React Query 5, TanStack Table 8
- Zustand, React Hook Form + Zod, axios
- Storybook 10, Vitest + Testing Library
- Cursor Rules/Skills, AGENTS.md, 기획 SSOT (`docs/`)
- MVP 백엔드: Express + Supabase(PostgreSQL) + Drizzle (`server/`)

## 이력서 불릿

### AI 활용 — 거버넌스 레이어 (`.cursor/`, `AGENTS.md`)

- `AGENTS.md`를 AI 에이전트·개발자 공통 온보딩 문서로 두고, 기술 스택·폴더 배치·ESLint 팀 규칙·상황별 참고 문서 맵을 한곳에 정의해 세션마다 컨텍스트 재주입 비용을 줄임.
- `.cursor/rules/` 7종을 globs별 자동 적용: `write-planning`(기획 작성), `design-system`(컴포넌트 토큰), `colocation`, `tanstack-query`, `react-typescript`, `git-workflow`, `nh-mockup-review`(목업 품질).
- `.cursor/skills/development-workflow`: 기획 문서 분석 → 테스트 시나리오 목록 → 테스트 선작성 → 구현 → `tsc`+`eslint` 루프를 스킬로 고정해 AI가 「구현만 먼저」하는 패턴을 차단.
- `.cursor/skills/write-planning`: `@index.md` 번호 SSOT, 카테고리 폴더 규칙, 문서 템플릿을 스킬화 — AI가 기획 문서를 추가할 때 목차·링크·번호 체계가 깨지지 않게 함.
- `.cursor/plans/프론트엔드_아키텍처_설계`: 스캐폴딩·토큰·라우팅·UI·auth·list-params·api-layer를 todo 단위로 분해해 AI가 단계별로 구현·완료 체크.

### AI 활용 — 기획 ( `docs/` )

- 서비스 전체·물류·요양원 3계층 목차(`docs/index.md`, `docs/logistics/@index.md`, `docs/nursing-hospital/@index.md`)로 도메인 범위를 분리; 번호는 `@index.md`에서만 관리하는 SSOT 규칙.
- 페이지 기획마다 ASCII 와이어프레임·필터 키·상태 탭·일괄 액션을 명시(`docs/logistics/order-management/order-list.md` 등) — AI가 화면을 추측하지 않고 구현할 수 있는 입력 스펙 제공.
- `docs/list-conventions.md`로 리스트 URL 동기화·파라미터 키·기본값 생략 규칙을 공통화; 개별 페이지는 고유 컬럼·필터만 정의.
- `docs/@agents/`(list-page, auth, layout, server-api, msw-mock): 작업 유형별로 AI가 읽을 최소 컨텍스트만 분리 — 전체 docs 일괄 로드 없이 필요 문서만 주입.

### AI 활용 — 디자인 (`DESIGN.md`, `mockup/`, `nh-ui-conventions.md`)

- `DESIGN.md`에 색·타이포 토큰을 YAML frontmatter로 기계 가독 형태로 정의; AI가 Tailwind `@theme`·컴포넌트에 토큰 하드코딩 없이 매핑.
- 요양원 화면은 `mockup/*.html`+CSS로 먼저 프로토타입(카탈로그·장바구니·입소상담·출금 등); React 이전에 레이아웃·인터랙션을 시각 검증.
- `nh-mockup-review.mdc` 4단계 체크리스트: DS 토큰 준수 → 요양원 치수 → UI 컨벤션 → **「AI스럽지 않게」**(과도한 그림자·마케팅 문구·균일한 더미 데이터·모바일 first 컨트롤 등 제거) — AI 생성 UI의 전형적 흔적을 리뷰 규칙으로 걸러냄.
- `docs/nursing-hospital/nh-ui-conventions.md`: 요양원 전용 필터 툴바 36px 통일·라벨 폭 고정·테이블 정렬 등 — 전역 DS는 건드리지 않고 product 층 규칙만 추가.

### AI 활용 — 개발 검증·핸드오프 (`docs/dev-logs/`, 테스트)

- 서버 API 변경 시 `docs/dev-logs/{페이지명}.md`에 UI 수정 포인트를 기록(`주문-목록.md`: `approved`→`received` 상태 변경, counts 키·SELECTABLE_STATUSES·BatchActionBar 영향 범위) — 서버 AI 세션과 UI AI 세션 간 인수인계 문서.
- development-workflow 스킬 우선순위에 따라 AI가 테스트를 먼저 작성: `orderQueries` 키 팩토리, `OrderListPage`·`OrderDetailPage`·`OrderBatchActionBar`, `usePrintInvoice` 단위/통합 테스트.
- 기획에 없는 내용은 코드 작성 중단·사용자 질문 후 기획 문서 수정 — AI 환각을 프로세스 단계에서 차단하는 가드레일.

### 라우팅·레이아웃 (`App.tsx`, `components/layout/`)

- `AuthLayout` / `DashboardLayout` / `AuthGuard`로 로그인·보호 구간 분리; 물류 도메인 라우트 선등록.
- `DashboardLayout`: `Header` + 접기 가능 `Sidebar` + `Outlet`; `useSidebarStore`(Zustand persist)로 사이드바 상태 유지.
- `RoleGuard`로 역할별 접근 제한 준비; `Header`에 알림 뱃지(`useNotificationStore`)·역할 라벨.

### 인증 (`hooks/useAuth.ts`, `lib/auth/`, `stores/auth-store.ts`)

- `LoginPage`: React Hook Form + Zod 검증; `tokenStore` + `useAuthStore`로 세션 관리.
- `apiClient` axios 인터셉터: Bearer 부착, 401 시 refresh 재시도, 실패 시 `/login` 이동.
- `docs/@agents/auth.md`에 토큰 갱신·자동 로그인 정책을 정리해 AI가 인증 코드 작성 시 참조.

### API·서버 상태 (`lib/api/`, `providers/AppProviders.tsx`)

- `@queries/` queryOptions 팩토리(`orderQueries.list/detail/counts`)로 queryKey·staleTime·queryFn 일원화.
- `QueryClient` 기본 staleTime 30s, retry 1; Vite proxy `/api` → Express, 프로덕션은 `VITE_API_BASE_URL` 교체.

### 리스트 공통 (`hooks/useListParams.ts`, `docs/@agents/list-page.md`)

- URL search params와 페이지·필터·정렬 완전 동기화; enum/date 타입별 파싱·기본값 생략.
- `list-page.md` 표준 트리(StatusTabs → FilterBar → BatchActionBar → DataTable → Pagination)를 주문 목록에 첫 적용 — 이후 배송·재고 리스트 확장 시 AI 복제 템플릿.

### 주문 관리 — 목록·상세·액션 (`routes/logistics/orders/`)

- 목록: 상태 탭 건수(`orderQueries.counts`), 필터·일괄 confirm/인쇄/prepare, 재고 부족 행 하이라이트, 엑셀 다운로드.
- 상세: 섹션 co-location(정보·품목·금액·배송·이력·메모), 상태별 단건 액션 버튼.
- `usePrintInvoice`: 숨김 iframe PDF 인쇄 → 배송준비 모달 순서; non-blocking `print()` 특성을 주석·테스트로 문서화.

### 디자인 시스템·Storybook (`components/ui/`)

- Button·Input·DataTable·Pagination·Modal·Tabs 등 원자 컴포넌트 + `*.stories.tsx`.
- `design-system.mdc`로 컴포넌트 편집 시 토큰·aria-label·Layout.Content 규칙 자동 적용.

### 구현 범위 (현재 코드 기준)

- **완료**: AI 워크플로 인프라 전체, 로그인, 레이아웃, 주문 목록·상세·일괄/단건·엑셀·인쇄, 주문 도메인 테스트.
- **스텁**: 배송·재고·정산·반품·설정·알림·비밀번호 재설정 — 라우트만, 기획·패턴은 준비됨.
- **기획·목업**: 요양원 관리자(`docs/nursing-hospital/`, `mockup/`) — React 미연결.

## STAR

### S1. AI 에이전트용 기획→구현 파이프라인 설계

- **S**: 요양원-물류 어드민을 소수 인원으로 빠르게 만들어야 했고, 기획·디자인·프론트·MVP API를 AI에 위임할 때 출력이 매번 달라지거나 기획과 어긋나는 문제가 예상됨.
- **T**: AI가 반복 실행 가능한 입력(기획 SSOT, 디자인 토큰, 작업별 에이전트 문서)과 출력 검증(TDD, ESLint, dev-logs 핸드오프) 체계를 프로젝트 루트에 구축할 것.
- **A**: `write-planning`·`development-workflow` 스킬, 7종 Cursor Rules, `AGENTS.md`·`docs/@agents/` 맵 작성; 기획은 `@index.md` 번호 SSOT·와이어프레임·공통 정책으로 분리; 디자인은 `DESIGN.md` 토큰 + `mockup/` + 「AI스럽지 않게」 리뷰 규칙; 구현은 기획 선독 → 테스트 선작성 → `useListParams`·queryOptions 등 재사용 패턴으로 주문 도메인 완성.
- **R**: 사용자 제공

### S2. 기획 SSOT + TDD로 AI 코드 품질 고정

- **S**: AI가 주문 상태명·API 스펙을 임의로 바꾸거나 테스트 없이 UI만 먼저 쓰면, 서버·프론트·기획 3곳이 어긋남.
- **T**: 상태 변경 같은 횡단 수정이 한 번에 전파되게 하고, AI 구현의 정답 여부를 자동 검증할 것.
- **A**: `approved`→`received` 변경 시 `docs/dev-logs/주문-목록.md`에 API·UI 영향 표 작성; `OrderListStatusTabs`·`OrderBatchActionBar`·`OrderDetailActionButtons`·`src/const/order.ts` 일괄 수정; `OrderListPage.test.tsx`·`orders.test.ts` 등으로 queryKey·탭·일괄 액션 회귀 방지; development-workflow 스킬로 「테스트 없이 구현」 금지.
- **R**: 사용자 제공

### S3. 출고 지시서 인쇄 후 배송준비 전환 UX

- **S**: 물류 담당자가 출고 지시서 인쇄 후 배송준비로 바꿔야 하나, 새 탭 PDF·인쇄 대화상자·후속 모달 타이밍이 겹치면 혼란.
- **T**: 현재 창 인쇄 UX와 인쇄 완료 후 배송준비 확인 모달 순서를 단건·일괄에 통일할 것.
- **A**: `printBlob` 숨김 iframe + `usePrintInvoice` 훅; `OrderBatchActionBar`·`OrderDetailActionButtons`에서 인쇄 → `pendingPrepareIds` → prepare API; non-blocking 특성 주석·테스트 문서화.
- **R**: 사용자 제공
