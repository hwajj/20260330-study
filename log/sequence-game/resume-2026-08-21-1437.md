# sequence-game

## 한 줄 요약
Firebase Auth·Realtime Database와 Express(Firebase Functions)를 묶은 멀티플레이어 Sequence 보드 게임 — 턴·보드·시퀀스 판정은 서버 권위로 두고, 클라이언트는 실시간 구독과 UI로 맞춘 풀스택 웹 게임 (백엔드·프론트엔드 단독 구현, 사용자 제공)

## 기술 스택 / 역할 키워드
- React 18, Vite, React Router DOM
- Jotai (전역 유저·알림·게임 상태 atom)
- Firebase Authentication (Google 팝업), Firebase Realtime Database 클라이언트 SDK
- Axios (Functions HTTP API 호출)
- Tailwind CSS, classnames, Font Awesome
- react-ga4 (페이지뷰)
- GSAP, react-slick (의존성 포함)
- Express on Firebase Functions, firebase-admin, shortid
- 역할: 프론트엔드(라우팅·상태·실시간 UI) + 백엔드(방·게임 API·승리 판정) 단독 (사용자 제공)

## 이력서 불릿

### client — 라우팅·레이아웃·분석
- Splash / Login / Lounge / `room/:roomId` 라우트를 React Router로 구성하고 MainLayout 하위에 인증 후 플로우를 배치함
- 경로 변경 시 react-ga4로 pageview를 전송해 화면 단위 사용 추적을 연결함

### client — 인증·유저 상태
- Firebase Google 팝업 로그인과 `onAuthStateChanged`로 세션을 복원하고, jotai `userAtom`에 유저를 반영함
- 로그인 성공 시 라운지로 이동하고, 미인증·와일드카드 경로는 로그인 화면으로 유도함

### client — 라운지(방 목록·참여)
- RTDB `rooms`를 `onValue`로 구독해 방 목록을 실시간 갱신함
- 생성·참여 전 게임 시작 여부·정원 초과를 클라이언트에서 선검증하고, Functions `join-room`/`create-room`으로 확정함
- `/userRoom`으로 기존 참여 방을 조회해 중복 대기 없이 해당 룸으로 리다이렉트함

### client — 게임룸·실시간 동기화
- `rooms/{roomId}` 전체를 구독해 플레이어·호스트·핸드·턴·보드·승패를 UI 상태에 반영함
- 호스트 부재 시 indexNumber 기준 승계를 RTDB에 기록해 방 운영이 끊기지 않게 함
- 게임 시작/중단/종료를 모달(Quit·Finished·Tutorial)과 알림 atom으로 사용자에게 전달함

### client — Board·상호작용 UI
- 보드 셀의 `occupiedColor` 변화를 이전 스냅샷과 비교해 최근 배치 위치를 하이라이트함
- 턴·선택 카드·시퀀스 인덱스에 따라 클릭 가능 영역을 제한하는 보드 UX를 구성함

### client — URL 딥링크 참여 훅
- `useJoinRoomOnUrlAccess`로 URL의 `roomId` 진입 시 기존 `userRoom` 확인 후 join 또는 소속 방으로 리다이렉트함
- 참여 실패 메시지를 API 응답에서 꺼내 알림으로 표시하고 라운지로 복귀시킴

### functions — 방 API
- shortid 방 생성, 짝수 인원 검증(`set-total-players`), 참여·퇴장, `userRooms` 매핑으로 “유저↔현재 방”을 서버에서 관리함
- CORS·JSON Express 앱을 `functions.https.onRequest`로 배포하고 로컬에서는 nodemon으로 기동함

### functions — 게임 로직(서버 권위)
- 인원별 핸드 장수·팀(blue/orange) 배정·덱 셔플·첫 턴을 `start-game`에서 일괄 초기화함
- `place-card`에서 턴·보유 카드·J 특수룰(제거/자유배치)·일반 배치를 검증한 뒤 턴 순환과 드로우를 수행함
- `checkWin`으로 5연속 시퀀스를 방향 검사하고 시퀀스 2개 달성 시 승자·종료 플래그를 RTDB에 기록함

## STAR

### 1. 실시간 멀티플레이 방·보드 동기화
- S: 여러 플레이어가 같은 보드를 보며 대기·진행해야 하는 웹 Sequence 게임인데, 폴링만으로는 턴·입퇴장 반영이 끊김
- T: 방 목록·룸 상태를 지연 없이 공유하고, URL로 초대된 사용자도 올바른 방에 들어가게 할 것
- A: 클라이언트는 RTDB `onValue`로 `rooms`/`rooms/{id}`를 구독하고, 생성·참여·퇴장·시작은 Express Functions로 확정. `userRoom`과 URL join 훅으로 중복 방·잘못된 진입을 정리. jotai로 유저·알림을 전역화하고 게임룸은 구독 데이터를 로컬 상태로 투영
- R: (숫자 미제공) 대기↔진행↔종료 전환과 다인 보드 동기화가 코드상 단일 RTDB 스냅샷 흐름으로 동작하도록 구성함. 백·프론트 단독 구현(사용자 제공)

### 2. 서버 권위형 카드 배치·시퀀스 승리 판정
- S: 클라이언트가 보드를 직접 쓰면 턴 치팅·잘못된 J 룰 적용이 가능함
- T: 카드 배치·특수 카드·승리 조건을 서버에서만 확정하고 UI는 결과를 반영하게 할 것
- A: `place-card`에서 턴·핸드·좌표·J(♠♥ 제거 / ♦♣ 자유배치)·시퀀스 칸 보호를 검증. `checkWin`으로 5연속·복수 시퀀스를 집계해 `gameFinished`/`winner`를 갱신. 클라이언트 Board는 점유색·시퀀스 강조만 담당
- R: (숫자 미제공) 게임 규칙의 신뢰 경계를 Functions+Admin SDK 쓰기로 모으고, 프론트는 구독·표현에 집중하는 구조를 확정함
