# 케어네이션 홈페이지 AI 챗봇 면접

## 면접 Q&A

### 레이어 분리 (core / host)

#### Q. `core`와 `host`를 나눈 이유는? 유지보수 관점에서 설명해 주세요.

A. 챗봇 UI(헤더, 말풍선, 푸터, 퀵버튼, 진단 카드)는 web·앱·고객센터 **어디서나 같아야** 하는데, 열리는 방식·userId·CSS·진단 포함 여부는 **플랫폼마다 달라요**. 처음부터 한 파일에 if로 분기하면 수정할 때마다 “웹은 됐는데 앱이 깨졌다”가 반복됩니다.

그래서 `core`에는 공통 UI 컴포넌트만 두고, `host`에는 “이 진입점에서만 필요한 것” — 예: 웹은 `onClose`+세션 삭제, 앱은 query `userId` 파싱, support는 진단 없는 Container — 을 뒀습니다. shared `ChatbotContainer`가 상담·진단 흐름의 중심이고, host는 거기에 옵션을 넘기는 얇은 래퍼예요. **바꿀 때 core를 고치면 세 군데 다 따라오고, host만 고치면 그 진입점만 바뀝니다.**

근거: `README.md` 폴더 구조, `host/web/ChatbotHomeHost.tsx`, `host/webview/ChatbotAppHost.tsx`, `host/chatbotOnly/ChatbotAppHost.tsx`

---

#### Q. `host/shared` Container와 `host/chatbotOnly` Container를 둘로 나눈 기준은?

A. `/chatbot/.../app` 라우트는 AI 이용상담 + AI 의료정보(진단)까지 필요하고, `/support`는 **고객센터에서 상담만** 쓰는 경로예요. 진단은 이미지 업로드, WebSocket, 응급 오버레이, 진행도 UI 등 코드량·상태가 많습니다.

support에 진단 분기를 전부 태우면 Container가 더 길어지고, 고객센터 쪽 버그 수정 때 진단 코드까지 건드릴 위험이 있어요. 그래서 상담 전용 Container를 `chatbotOnly`에 두고, app/webview용은 shared에 진단까지 포함시켰습니다. **기능 범위가 다른 진입점은 파일을 나눠서 읽기·수정 범위를 줄였습니다.**

근거: `App.tsx` 라우트 주석, `host/chatbotOnly/ChatbotContainer.tsx`, `host/shared/ChatbotContainer.tsx`

### 진입점·라우팅

#### Q. `/app`과 `/support` 라우트를 나눈 기준과 프론트 차이는?

A. **기준**: 앱 메인에서 쓰는 풀 기능 챗봇(`/app`, 진단 O) vs 고객센터 WebView에 embed되는 상담 전용(`/support`, 진단 X).

**프론트 차이**:
- `/app` → `webview/ChatbotApp` + shared Container, `userType`·테마 CSS(pro/mat) 설정, 진단 모드·WS 연동.
- `/support` → `chatbotOnly/ChatbotApp` + chatbotOnly Container, 메인 가이드 아래 상담 패널만 (`consultPanelOnMainGuide` 등), 진단 state·WS 없음.
- 둘 다 WebView라 `useSpaMainSiteHeadCssIsolation`으로 메인 사이트 CSS는 끄고 챗봇 CSS만 씁니다.

근거: `App.tsx` 298~302행, `chatbotOnly/ChatbotApp.tsx`, `webview/ChatbotApp.tsx`

### 상태 설계

#### Q. Redux에 세션만 두고 `messages`는 로컬 state인 이유는?

A. **Redux에 둔 것** (`sessionId`, `userType`, `currentUserId`): API 호출·세션 생성·앱/웹 간 “누구로 로그인했는지”처럼 **여러 hook·컴포넌트가 공유**하는 식별 정보.

**로컬 `messages`**: 말풍선 추가·타이핑·스크롤·subQuestions 붙이기처럼 **렌더 한 사이클 안에서 자주 바뀌고**, Container와 ChatbotChat 사이에서 props로 넘기기 쉬운 데이터. Redux에 넣으면 타이핑 한 글자마다 dispatch·리렌더 범위가 커지고, 진단 tail 교체 같은 배열 조작도 slice action이 많아집니다.

세션 ID만 Redux에 두고 “대화 내용은 이 화면 인스턴스 state”로 두면, 챗봇 닫을 때 `setMessages([])`로 정리하기도 단순합니다. (웹 Footer는 닫을 때 messages 비움, sessionId는 Redux에 남을 수 있음 — host 정책에 따름.)

근거: `chatbotSlice.ts`, `useChatSession.ts`, `Footer.tsx` handleChatbotButtonClick

### AI 이용상담·퀵질문

#### Q. 퀵질문 L0~L4와 audience 필터는 어떻게 동작하나?

A. API/mock 트리에서 **level 0**은 섹션(자주 찾는 질문·서비스 이용·기타 문의), **1~2**는 서비스·이용 의도 분기, **3**은 리프(클릭 시 바로 POST `/chat`, `is_direct_question: true`).

`mapUserTypeToAudience`로 Redux `userType`(guardian/caremate) → `"보호자"` / `"케어메이트"`로 바꾸고, `filterQuickQuestionsByAudience`로 `"공통"` + 해당 audience만 남깁니다. 정렬은 `order_index` 후 audience 전용 항목을 공통보다 앞에.

분기 노드 클릭 → `getQuickQuestionChildren(parentId)` → 가이드 bot 메시지 + `subQuestions`. 리프 클릭 → `getPostAnswerSiblings`로 클릭한 항목 제외 형제를 답변 아래에 다시 보여줌. 형제 풀은 `quickSiblingPool`을 메시지에 저장해 다음 클릭 때도 같은 기준으로 계산.

API 장애 시: env `NEXT_PUBLIC_CHATBOT_QUICK_USE_MOCK` 또는 children 실패 시 `mockConsultQuickTree` 폴백.

근거: `types/chatbot.ts` QuickQuestion level 주석, `consultQuickUtils.ts`, `useConsultQuickRoot.ts`, `ChatbotContainer.tsx` handleConsultBranchClick / handleConsultLeafClick

### AI 의료정보·WebSocket

#### Q. 진단 WebSocket 이벤트 후 GET을 80ms 디바운스한 이유는?

A. 서버가 `task_changed` 직후 `status_changed`나 `new_message`를 **짧은 간격으로 연속** 보낼 수 있어요. 이벤트마다 바로 `getDiagnosisSession`을 치면 같은 세션에 GET이 여러 번 가고, `setMessages`·진행도·선택지 state가 연속으로 갱신되면 UI가 튈 수 있습니다.

`scheduleRefresh`에서 80ms 디바운스로 **마지막 이벤트 묶음 후 한 번만** GET하도록 했습니다. `task_changed`만 온 경우에는 타이핑 점 UI만 켜고, `waiting_input` / `completed` / `emergency` / `new_message`일 때 refresh + 타이핑 끔. 연결 직후 `onopen`에서도 한 번 GET해 푸시 누락을 보완합니다.

ping/pong은 연결 유지용으로, JSON이 아닌 평문 `"ping"` 수신 시 `"pong"` 응답.

근거: `useDiagnosisSessionWebSocket.ts`, `ChatbotContainer.tsx` refreshDiagnosisSession

#### Q. 앱 WebView에서 세션 생성 후 대화 타임라인이 안 날아가게 한 처리는?

A. 홈페이지 웹은 챗봇 열 때마다 session/history를 다시 세팅해도 괜찮지만, 앱 WebView는 **한 화면에서** 「AI 이용상담」 선택 → `moveToConsult` → `ensureSession`으로 `sessionId`가 생기면 `useEffect` dependency에 `sessionId`가 들어 있어 effect가 재실행됩니다.

이때 `setMessages([가이드])`만 하면 사용자·봇 메시지가 다 지워집니다. `ChatbotApp.tsx`에서 `currentUserId !== "Homepage"`일 때 `appInitialGuideSeededRef`로 **가이드 시드를 최초 1회만** 하도록 막았습니다. 홈페이지 userId일 때만 sessionId 변경 시 history 복원 로직을 탑니다.

근거: `webview/ChatbotApp.tsx` 112~119행 주석 및 구현

### UX·렌더

#### Q. 마크다운 타이핑을 grapheme 단위로 한 이유는?

A. `react-simple-typewriter`나 문자 단위 slice는 이모지(🇰🇷), 일부 한글 조합, ZWJ 이모지에서 **글자가 쪼개지거나** 타이핑 중 레이아웃이 흔들릴 수 있어요. `grapheme-splitter`로 사용자에게 보이는 ** grapheme cluster** 단위로 한 칸씩 보여줍니다.

마크다운은 `preprocessMarkdownText`로 `#` 제목 앞 빈 줄 등을 보정한 뒤, `renderLightByLines`로 줄 단위 가벼운 렌더. 타이핑 중 minHeight를 잡아 말풍선 높이가 줄었다 늘었다 하지 않게 했습니다. 트레이드오ff: 전체 응답을 grapheme 배열로 쪼개므로 **아주 긴 답변**에서는 타이핑 effect 비용·시간이 길어질 수 있고, 마크다운은 타이핑 **완료 전**엔 불완전한 문법일 수 있어 `preprocess`로 최소한만 보정합니다.

근거: `MarkdownTypewriter.tsx`, `ChatbotChat.tsx` lastBotMsgIdx 타이핑 분기
