# 케어네이션 홈페이지 AI 챗봇 (homepage-carenation-react)

## 한 줄 요약

케어네이션 홈페이지·앱 WebView에 AI 이용상담·의료정보 챗봇을 붙이고, UI·진입점·훅·API를 레이어로 나눠 웹/앱/고객센터에서 같은 동작을 유지보수하기 쉽게 맞춘 프론트엔드 작업.

## 기술 스택 / 역할 키워드

- React 19, TypeScript, Next.js 16
- Redux Toolkit (챗봇 세션·사용자 유형), TanStack React Query (퀵질문 캐시)
- axios (챗봇·진단 REST), WebSocket (진단 세션 동기화)
- react-markdown, grapheme-splitter (봇 응답 타이핑), body-scroll-lock
- SCSS — `v002/scss/chatbot` (보호자/케어메이트 테마)

## 이력서 불릿

### 레이어 분리 (core / host / hook / api)

- 챗봇 코드를 `core`(헤더·채팅·푸터·진단 UI), `host`(웹·앱·고객센터 진입), `hook`(세션·전송·WS), `api`, `store`로 나눠 **수정 범위를 좁히고** web/webview/support 간 동작 불일치를 줄임.
- `host/shared/ChatbotContainer`에 상담·진단 공통 흐름을 모으고, 고객센터 전용(`/support`)은 진단 없는 `host/chatbotOnly/ChatbotContainer`로 분리해 **불필요한 분기를 host 밖으로 밀어냄**.

### 웹 오버레이 (host/web)

- Footer 플로팅 버튼(`ChatbotBotton`) 클릭 시 세션 생성·히스토리 복원 후 오버레이 챗봇을 연다.
- `open-chatbot` CustomEvent로 페이지 어디서든 챗봇을 열 수 있게 하고, `ChatbotHomeHost`는 lazy 로드로 초기 번들 부담을 줄임.
- 웹 종료 시 `clearSessionOnClose`로 세션을 정리하는 등 host 옵션으로 플랫폼별 차이만 주입.

### 앱 WebView (host/webview, host/chatbotOnly)

- `/chatbot/{carenation|caremate}/app` — AI 이용상담 + AI 의료정보(진단) 포함, 쿼리 `userId`·경로로 `currentUserId`·`userType`(보호자/케어메이트) 설정.
- `/chatbot/{carenation|caremate}/support` — 고객센터 연동용, 상담만 제공(진단 UI·플로우 제외).
- 앱 진입 시 `clearSession` 후 가이드 메시지 시드; WebView는 `sessionId` 생성 후에도 타임라인이 덮어쓰이지 않도록 `appInitialGuideSeededRef`로 **최초 1회만** 가이드를 넣음.
- WebView에서 메인 사이트 CSS와 충돌을 막기 위해 `useSpaMainSiteHeadCssIsolation`으로 `data-spa-main-site-css` 링크를 비활성화하고, 챗봇 전용 CSS(`chatBot.css`, `chatBotPro.css` / `chatBotMat.css`)를 동적 주입.

### 세션·상태 (hook / store)

- Redux `chatbotSlice`: `sessionId`, `currentUserId`, `userType`, `hasStartedChat` — **세션 식별·사용자 맥락**만 전역 관리.
- 대화 타임라인 `messages`는 컴포넌트 로컬 state — 렌더·스크롤·타이핑과 밀접해 전역화하지 않음.
- `useChatSession`: 세션 생성(중복 ID 시 최대 3회 재시도), `ensureSession`, 히스토리 복원(`getChatbotSessionById`), 삭제(`deleteChatbotSession`), userId 기반 최근 로그 복원(`getChatLogs`).

### AI 이용상담 (consult)

- `useChatbotController`: 사용자/봇 메시지 낙관적 추가, API 전송, 에러 시 상태 롤백, 모바일 body scroll lock, 사용자 스크롤 시 자동 스크롤 해제.
- 퀵질문 L0~L4 트리: `useConsultQuickRoot` / `ConsultQuickGuidePanel` — 자주 찾는 질문·서비스 이용·기타 문의 섹션, `target_audience`(보호자/케어메이트/공통) 필터·정렬.
- 분기 노드 클릭 → `getQuickQuestionChildren`으로 하위·가이드 문구 로드; 리프 클릭 → `is_direct_question: true`로 POST `/chat`.
- L4 답변 후 형제 질문은 `subQuestions`·`quickSiblingPool`로 답변 아래 재노출; 없으면 타이핑 완료 후 메인 가이드(`MAIN_GUIDE_TEXT`) 추가.
- API 실패·mock 전환: `chatbotQuickEnv` env 플래그, children API 실패 시 mock 폴백.

### AI 의료정보 (diagnosis)

- `ChatbotContainer` 내 `mode: "diagnosis"`: 이미지 최대 3장 multipart(`createDiagnosisSession` / `postDiagnosisSessionMessage`), 진행도(`questions_asked` / `max_questions`) 표시.
- `useDiagnosisSessionWebSocket`: `task_changed` → 타이핑 점 UI, `status_changed`·`new_message` → 80ms 디바운스 후 GET `/sessions/:id`로 스냅샷 동기화; ping/pong 처리.
- 진단 시작 전 메시지는 `diagnosisMessageStartIndexRef`로 head 유지, 서버 메시지만 tail 교체 — **상담 히스토리와 진단 구간 분리**.
- 완료·응급(`emergency`) 시 구조화 결과 카드·응급 오버레이; 중단·상담 전환 시 결과를 상담 타임라인에 persist 메시지로 이어 붙임.

### UX·렌더 (core)

- `MarkdownTypewriter`: grapheme 단위 타이핑(이모지·한글 조합 안정), `preprocessMarkdownText`로 제목 블록 인식 보정.
- `ChatbotChat`: 마지막 bot 메시지에만 타이핑 효과, 진단 가이드 쌍·메인 가이드 버튼(AI 이용상담 / AI 의료정보) 분기 렌더.
- `useViewportHeightVar`: iOS WebView 키보드·주소창 대응( iOS 제외 옵션).

### 스타일 (v002)

- `v002/scss/chatbot`: layout·message·input·quick·diag·popup·maintenance 컴포넌트 SCSS, `_pro.scss` / `_mat.scss` 테마로 보호자·케어메이트 UI 분기.
- 빌드 산출물은 `homepage-carenation-react/public/css/chatbot/`에서 서빙.

## STAR

### 1. web / webview / 고객센터 진입점 — host 레이어로 공통화

- S: 같은 챗봇 UI·상담·진단 동작을 홈페이지 오버레이, 앱 WebView 전체 화면, 고객센터 연동(`/support`) 세 곳에서 써야 했고, 진입 방식·userId·CSS·진단 유무가 플랫폼마다 달랐음.
- T: 코드 복붙 없이 **한 곳 수정이 세 진입점에 반영**되도록 구조를 잡고, 플랫폼별 차이는 host에만 두기.
- A:
  - 공통 UI·입력·스크롤·모드 전환을 `core`와 `host/shared/ChatbotContainer`에 모음.
  - web은 `ChatbotHomeHost`(헤더·종료 시 세션 정리), webview는 `ChatbotAppHost`(앱 userId·유지보수 화면), support는 `chatbotOnly` Container(상담만)로 host 분리.
  - `HostOptions`(`getUserId`, `onQuickSendFocus`)로 host별 userId·포커스 정책만 주입.
  - README·폴더 구조에 core/host 역할을 문서화.
- R: (코드 기준) web/webview가 shared Container를 재사용하고, support만 별도 Container — **중복 UI 수정 지점을 core/host 경계로 줄임**.

### 2. AI 의료정보와 AI 상담 — 한 Container에서 모드 전환·결과 이관

- S: 메인 가이드에서 「AI 이용상담」「AI 의료정보」 두 갈래로 나가야 했고, 진단은 이미지·WS·선택지·응급 알림이 있어 상담과 API·UI 흐름이 달랐음. 진단 후 다시 상담으로 돌아올 때 대화 맥락이 끊기면 안 됨.
- T: 사용자 입장에선 **한 챗봇 안에서** 모드가 바뀌는 UX를 유지하면서, 상담 REST와 진단 REST/WS를 각각 맞게 연결하기.
- A:
  - `ChatbotMode`(`main` | `consult` | `diagnosis`)로 화면·푸터 모드(`mainLocked` / `consult` / `diagnosisInput` / `diagnosisProgress`) 분기.
  - 진단: multipart 전송 → WS 이벤트 → 디바운스 GET으로 메시지·선택지·진행도 동기화; `diagnosisMessageStartIndexRef`로 상담 head + 진단 tail 구조 유지.
  - 완료·중단·「AI 이용상담」 재선택 시 `diagnosisResult` / `emergencyDiagnosis` persist 메시지와 가이드 버블을 상담 타임라인에 append.
  - `useDiagnosisSessionWebSocket`·`parseDiagnosisWebSocketData`로 ping/pong·JSON 이벤트 타입별 처리를 hook으로 분리.
- R: (코드 기준) 상담·진단이 `ChatbotContainer` 한 오케스트레이션 지점에서 연결되고, 진단 결과가 상담 `messages`에 남도록 구현됨.
