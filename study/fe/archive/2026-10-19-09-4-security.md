## 정리

### 한 줄

**XSS**는 스크립트 실행을 막고(이스케이프·sanitize·CSP), **CSRF**는 쿠키 세션 위조 요청을 막으며(SameSite·CSRF 토큰), 토큰·CDN·iframe까지 **한 세트**로 방어층을 쌓는다.

### 핵심

- **XSS**: 악성 HTML/JS가 페이지에 실행. `innerHTML`, `dangerouslySetInnerHTML`, URL `javascript:` 등. React는 텍스트 노드 기본 이스케이프; HTML 삽입은 DOMPurify 등 **sanitize + CSP 2차**.
- **CSRF**: 로그인된 사용자 브라우저가 **쿠키를 자동 실어** 위조 POST/GET. XSS와 다름 — “실행”이 아니라 “정상 사용자 행위 위장”. SameSite(Lax/Strict), CSRF token, custom header.
- **CSP**: `Content-Security-Policy`로 inline script·외부 origin 제한. XSS 완화·report-uri 모니터링.
- **토큰 위치**: localStorage는 **XSS에 JS로 탈취** 가능. HttpOnly 쿠키는 JS 접근 불가 → XSS에 상대적으로 강하지만 **CSRF 대비** 필요(Day 6·26).
- **Clickjacking**: 투명 iframe으로 클릭 유도 → `X-Frame-Options: DENY/SAMEORIGIN` 또는 CSP `frame-ancestors`.
- **SRI**: `<script integrity="sha384-…">` — CDN 변조 시 실행 거부.
- **Mixed Content**: HTTPS 페이지의 HTTP 자원 차단/경고; `Secure` 쿠키와 연동.

### 흐름

```
입력·렌더
  → 사용자 HTML? → sanitize · CSP
  → API auth → HttpOnly + SameSite + CSRF token
  → 서드파티 script → SRI + CSP allowlist
  → 임베드 → frame-ancestors
배포 → HTTPS 전 구간 · secret은 NEXT_PUBLIC/VITE에 금지
```

### 차이·함정

| 대비 | 한 줄 |
|------|--------|
| XSS vs CSRF | 스크립트 실행 vs 세션 쿠키 위조 요청 |
| escape vs sanitize | 텍스트 vs 허용 태그 subset HTML |
| HttpOnly vs localStorage | XSS 탈취 난이도 vs CSRF 이슈 |
| CSP vs CORS | 실행 정책 vs origin 읽기 허용 |
| X-Frame vs frame-ancestors | 레거시 헤더 vs CSP 통합 |

### 면접 한 방

- **Q:** CSRF와 XSS 차이, 토큰을 localStorage에 두면?
- **답:** XSS는 페이지에서 악성 JS 실행, CSRF는 로그인 쿠키로 위조 요청. localStorage 토큰은 XSS 한 번에 탈취당한다. HttpOnly 쿠키는 JS가 못 읽지만 CSRF 방어는 별도. CSP·SameSite·sanitize로 층을 나눈다.
