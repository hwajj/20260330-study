## 정리

### 한 줄

**TCP**로 신뢰 연결, **TLS**로 암호화·인증, **HTTP/2**가 한 연결 **multiplex**로 HOL을 완화하고, **DNS** 왕복이 첫 로드에 더해지며 **preconnect** 등으로 TTFB(Web Vitals)를 줄인다.

### 핵심

- **TCP vs UDP**: TCP — handshake·재전송·순서. UDP — 낮은 지연, 손실 허용(QUIC/HTTP3·실시간).
- **TLS**: 인증서로 서버 신원, 대칭키로 본문 암호화. **추가 RTT** — TLS 1.3·session resumption·0-RTT(주의)로 완화.
- **HTTP/1.1**: connection당 요청 serial(keep-alive로 reuse). 큰 JS many files → **head-of-line blocking**.
- **HTTP/2**: 한 TCP에 **stream multiplex**, **HPACK** header compress. Server push는 실무에서 덜 씀.
- **HTTP/3**: **QUIC over UDP** — connection migration, loss 시 stream별 영향↓.
- **DNS**: name → IP. **Recursive lookup chain** — TTFB 전 hidden cost. **dns-prefetch / preconnect** (`<link rel="preconnect" href="https://api...">`).
- **LB**: L4(IP/port) vs L7(URL·header) — sticky session·TLS termination at LB.

### 흐름

```
첫 방문 https://app.example.com
  DNS lookup → TCP SYN-SYN/ACK → TLS ClientHello... → HTTP GET
  → (HTTP/2) many assets on one connection parallel streams

[최적화]
  HTML head: preconnect API origin, CDN
  HTTP/2 + bundle split balance (Day30)
```

### 차이·함정

| 대비 | 한 줄 |
|------|--------|
| TCP vs TLS vs HTTP | transport vs crypto vs app |
| H2 vs H3 | TCP HOL vs QUIC streams |
| CNAME vs A | alias vs IP |
| keep-alive vs HTTP/2 | reuse vs multiplex |
| REST vs WebSocket | request/response vs persistent |

### 실무 연결

- **Core Web Vitals TTFB**: DNS+TLS+server — CDN edge(13-3)가 TLS termination 가까이.
- API **다른 subdomain** — preconnect + CORS preflight(OPTIONS) 추가 RTT.
- WebSocket(08-3): HTTP upgrade, LB **sticky**·timeout 설정 필요.

### 면접 한 방

- **Q:** HTTP/2가 1.1보다 나은 이유, HTTPS handshake 부담은?
- **답:** 한 연결에서 여러 요청을 multiplex해 HOL을 줄이고 헤더를 압축한다. HTTPS는 TLS handshake RTT가 붙어 TTFB가 늘 수 있어 TLS 1.3, session reuse, preconnect, CDN으로 완화한다.

### 통과선 스크립트

1. TCP 3-way 한 줄.
2. TLS = cert + encrypt, cost RTT.
3. H2 multiplex vs H1 serial.
4. H3 QUIC 감각.
5. DNS delay → prefetch/preconnect.
6. L7 LB = URL routing.
