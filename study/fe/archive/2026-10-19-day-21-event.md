## 정리

### 한 줄

이벤트는 캡처→타깃→버블로 흐르고, 부모 한곳에 위임하면 동적 목록도 싸게 처리하며, 기본동작 취소와 전파 중단은 **독립**이다.

### 핵심

- **구독**: `addEventListener(type, handler, { capture? })`. 기본은 버블 단계.
- **3단계**: Capturing(내려감) → Target → Bubbling(올라감).
- **Delegation**: 부모 리스너 하나 + `event.target`/`closest`로 자식 판별. 카드 그리드·테이블 행에 필수 감각.
- **preventDefault**: 링크 이동·폼 submit 등 **브라우저 기본** 막기. 전파는 계속될 수 있음.
- **stopPropagation**: 위/아래 **전파** 중단. 기본 동작과는 별개 — 둘 다 필요할 수 있음.
- React: 합성 이벤트가 루트에 위임하는 모델과 맞닿음. 핸들러에서 상태를 바꾸면 Redux/URL이 **다음 렌더의 입력**이 된다.

### 흐름

```
사용자 클릭
  → (capture) window → … → target
  → target handlers
  → (bubble) … → document
  → handler: setState / dispatch / setSearchParams
  → 리렌더·fetch
```

care 카드·필터 토이:

```
ICard 클릭 or 필터 change
  → (위임/핸들러) payload = card id / filter value
  → Redux auto slice 갱신 및/또는 URL ?filter=
  → 목록 queryKey 반영
```

### 차이·함정

| 대비 | 한 줄 |
|------|--------|
| capture vs bubble | 내려오며 vs 올라가며 — 기본은 bubble |
| preventDefault vs stopPropagation | 기본동작 vs 전파 |
| target vs currentTarget | 실제 발생 요소 vs 리스너 부착 요소 |
| 자식마다 리스너 vs 위임 | 메모리·동적 추가 비용 vs 한곳 처리 |
| stopImmediatePropagation | 같은 노드 다른 리스너까지 끊음(드물게) |

### 실무 연결

- **care `redux/states/auto/auto.ts` · ICard**: 자동결제/카드 도메인 상태. 카드 선택·표시에 쓰는 인터페이스 — 클릭 이벤트로 고른 카드 id를 슬라이스에 넣고 결제 위저드가 읽는다. 이벤트 → Redux가 **클라이언트 상태** 경로.
- W4 목 토이: 필터 1개를 URL에 추가 — `onChange`에서 `setSearchParams`, 북마크 가능. 이벤트 핸들러가 URL-sync의 진입점.
- dailycare HistoryPage 탭 클릭도 같은 계열: 클릭 → URL `tab` → queryKey.

### 면접 한 방

- **Q:** 이벤트 위임의 장점과 preventDefault/stopPropagation 차이는?
- **답:** 자식이 많거나 동적으로 생겨도 부모 리스너 하나로 처리해 등록·메모리 비용을 줄이고 target으로 판별한다. preventDefault는 기본 동작(제출·이동)을, stopPropagation은 버블/캡처 전파를 막으며 서로 독립이다. 흐름은 캡처→타깃→버블.

### 통과선 스크립트

1. 이벤트 흐름 3단계.
2. 위임: 왜 목록/카드에 유리한지.

4. target vs currentTarget.
5. (회사) ICard 선택 이벤트 → auto slice / URL 필터 토이로 상태·공유.
