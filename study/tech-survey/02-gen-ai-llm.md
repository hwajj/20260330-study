## 진행

### 토큰·토큰화

- **토큰:** 모델이 읽는 최소 단위(단어 조각·문자 조합). **토큰화**로 텍스트 → ID 시퀀스.
- **연결:** API **과금·속도·컨텍스트 한도**는 대부분 **토큰 수** 기준.

### 컨텍스트 윈도

- **정의:** 한 번의 forward에 넣을 수 있는 **토큰 상한**(프롬프트 + 생성 합).
- **넘으면:** 앞부분 **잘림**, **요약** 후 넣기, **RAG**로 필요한 조각만 검색해 넣기, 대화 **윈도잉**.

### pretrain · fine-tune · inference

| 단계 | 하는 일 | 비용·특징 |
|------|---------|-----------|
| **pretrain** | 웹·코드 등 대량 코퍼스로 다음 토큰 예측 등 **일반 능력** | GPU·시간 매우 큼, 1회 |
| **fine-tune** | 도메인·스타일·태스크 데이터로 **가중치 추가 학습**(또는 LoRA 등) | pretrain보다 작지만 데이터·검증 필요 |
| **inference** | 고정 가중치로 **새 입력 → 출력** | 학습 없음; **latency·GPU·토큰당 비용** |

` 실제 inference에서는 사용자의 텍스트를 tokenization하여 토큰 ID로 변환하고, 대화 내용과 필요한 정보들을 context window가 허용하는 토큰 범위 안에 넣은 뒤 이미 학습된 가중치로 출력을 생성하며, 이때 토큰 수는 비용·속도와 관련되고 context window를 초과하는 정보는 직접 볼 수 없기 때문에 잘림·요약·chunking·RAG·sliding window 등의 방법으로 필요한 정보만 윈도 안에 넣어야 한다.`

### Foundation 모델 4요소

- **아키텍처:** Transformer + self-attention 등 **확장 가능한 구조**
- **데이터:** 규모·다양성·저작권·편향(무엇을 넣었는지가 한계를 만듦)
- **compute:** pretrain·대규모 실험에 필요한 **연산·인프라**
- **alignment / safety:** RLHF·지시 따르기·거부 정책 등 **사용 목적에 맞게 조정**

`AI 모델은 Transformer와 self-attention 같은 아키텍처를 기반으로 대규모 데이터와 Compute를 활용해 pretrain을 수행하여 일반적인 언어·지식 패턴을 학습하고, 이렇게 만들어진 범용 모델을 Foundation 모델이라고 하며, 이후 alignment와 safety를 통해 사람의 의도를 따르고 안전하게 동작하도록 조정할 수 있다. `

### Transformer·self-attention

- 각 토큰이 **다른 모든 토큰과의 관련도**를 한 번에 계산 → 문장 **앞뒤 장거리** 의존(대명사·조건)을 RNN 한 스텝씩보다 잘 잡는 직관.

### 통과선 — 학습 vs 추론 (30초) + 컨텍스트 한계 (1분)

**학습 vs 추론:** pretrain·fine-tune은 **가중치를 바꾸는 단계**(오프라인·비쌈). inference는 **이미 학습된 가중치로만** 생성(온라인 서비스·토큰 과금). prompt·RAG는 **inference 위에서** 입력을 만드는 기법.

**컨텍스트 한계:** 모델은 윈도 밖 텍스트를 **직접 보지 못함** → 긴 문서·전체 코드베이스는 한 방에 불가. **잘림**하면 앞맥락 손실, **환각**은 학습 지식으로 빈칸을 채울 때. **대응:** RAG·요약·도구(파일 읽기)·멀티턴 압축 — 모두 **한도 안에 필요한 정보만** 넣는 설계.

### 4단 설명 — 컨텍스트 윈도

1. **정의:** 한 번에 처리 가능한 **최대 토큰 길이**.
2. **배경:** attention·메모리·비용이 입력 길이에 따라 **제곱 또는 선형**으로 커져 실무 한도가 생김.
3. **구성(대응):** chunking, RAG, sliding window, 요약, 외부 도구.
4. **한계:** 검색 miss·요약 왜곡·오래된 대화는 여전히 **정보 손실**.

## 메모

### Fine-tune vs prompt vs RAG (§3)

| 방법 | 언제 | 한 줄 |
|------|------|--------|
| **Prompt / ICL** | 범용 모델 + 예시·지시로 **당장** 형식·톤 맞추기 | 가중치 안 바꿈; 윈도·일관성 한계 |
| **Fine-tune** | **고정 도메인·포맷·용어**를 반복적으로 맞춰야 할 때 | 데이터·재학습 비용; drift 시 재학습 |
| **RAG** | 답이 **내부 문서·최신 KB**에 있고 환각 줄이기 | retrieval 품질이 병목; stale·chunk 경계 |

`Foundation 모델을 하나 만들어 놓고, "이 모델을 특정 목적에 어떻게 사용할 것인가?"라는 문제에 대한 서로 다른 접근이 Prompt/ICL, Fine-tune, RAG.`
`이렇게 학습된 Foundation 모델은 필요에 따라 fine-tune으로 특정 도메인·태스크에 맞게 가중치를 추가 학습하거나, prompt/ICL로 지시와 예시를 제공하거나, RAG로 외부 문서·최신 정보를 검색해 입력에 추가하는 방식으로 활용할 수 있다.`
